# 00-功能介绍

本教程介绍如何在 Y3 地图中连接 WebSocket 服务，以及如何在这套连接能力之上接入 Nakama 等开源游戏服务端框架。

相较于直接使用 TCP，WebSocket 有成熟的协议、客户端库和服务端生态，适合聊天、匹配、房间状态、服务端推送等需要长连接的功能。

<span id="当前客户端架构" className="legacy-anchor" />

## 当前客户端架构 {#client-architecture}

示例项目采用“Python 后台 I/O + Lua 主线程事件分发”的结构：

1. 每个 WebSocket 连接由一个 Python 后台线程独占，连接握手、发送、接收和关闭都在线程内执行。
2. Lua 与 Python 之间通过线程安全的发送队列、接收队列和连接状态通信。
3. 所有连接共用一个 Lua 客户端定时器，每 0.05 秒批量读取状态和消息。
4. 业务代码使用 `on_connected`、`on_message`、`on_error` 和 `on_closed` 回调，不需要自己轮询。
5. 没有活动连接时，Lua 调度器会自动停止。

这种设计把可能持续数秒的网络连接超时移出游戏线程。即使服务端端口未开放、被防火墙丢弃或连接超时，游戏镜头、单位操作和其他 Lua 定时器也不会被阻塞。

内部仍然需要一个短周期定时器，因为 Python 后台线程不能直接安全调用 Lua 游戏对象。这个定时器只负责把队列中的结果转移到 Lua 主线程，不承担网络 I/O。

<span id="已验证范围" className="legacy-anchor" />

## 已验证范围 {#verified-features}

当前实现已经在真实 Y3 游戏客户端中验证：

- 连接调用立即返回，防火墙式超时不会卡住游戏线程。
- WebSocket 连接、发送、批量接收和关闭正常。
- 连续消息保持顺序。
- Nakama 的 coroutine 和 callback 连接方式都会等待真实握手结果。
- 成功、失败和断开回调不会重复触发。
- 连接结束后后台线程和会话可以完整释放。

<span id="使用边界" className="legacy-anchor" />

## 使用边界 {#limitations}

本项目面向熟悉 Lua、Python 和网络服务部署的开发者。当前示例尚未提供自动重连、发送队列上限、心跳协议、离线消息恢复和生产级监控；这些能力应根据业务协议补充。

公网部署时请使用 `wss`、鉴权、强密码和最小化端口暴露。不要把示例密钥、数据库密码或调试端口直接用于正式环境。
