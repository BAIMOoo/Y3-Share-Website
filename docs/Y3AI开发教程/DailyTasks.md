# 日常开发任务

完成[环境配置](./EnvironmentSetup.md)和客户端配置后，从下面选一个任务。Lua 是游戏脚本；物编是物体编辑器中的单位、技能等配置；UI 是玩家看到的界面。

## 一轮任务的操作顺序

1. 保存工程，给已有项目留一份备份或 Git 版本。
2. 告诉 AI 要改哪个文件或对象、希望出现什么结果，让它先检查现有内容并给出计划。
3. 确认计划后实施，运行地图，对照该任务的完成标准检查画面、交互和日志。
4. 有问题时按[排查问题](./Troubleshooting.md)修复并复测；通过后检查文件改动，保存结果。

下面的提示词可以按自己的项目填写具体对象后发送。

## 整理需求与计划

把大需求拆成每一步都能检查的小任务：

```text
请把“每 20 秒刷新一波、每五波增加一个特殊单位”拆成实施步骤。
先读取当前工程，列出要确认的单位类型、玩家、位置和结束条件。
每一步说明改哪些文件、怎样检查结果；本次先规划普通波次。
```

**完成标准：**每一步有明确范围和可观察的结果，未确定的参数已经列出。

## 编写或修改 Lua

提供目标模块、触发条件和错误日志。让 AI 沿用项目现有的事件与资源清理方式。

```text
检查指定技能在单位死亡后仍继续触发的问题，先读现有实现和本地 API，再做最小修复。
完成后检查 Lua 诊断，并复测正常释放、单位死亡和重新进入游戏时的行为。
```

**完成标准：**没有新增诊断问题，三个场景都符合需求。项目已加载 `y3-lua-pipeline`、`y3-lua-review` 时，可使用这些流程。

## 创建或批量修改物编

先做一个样本，确认后再批量生成。

```text
以选定单位为样本，规划 20 个单位物编：10 个普通单位、5 个首领、5 个英雄。
列出名称、模型和属性字段，先只制作 1 个普通单位，不覆盖已有 ID。
样本在编辑器和游戏检查通过后，再制作其余单位。
```

**完成标准：**ID 唯一，字段和资源引用正确，单位能正常加载。修改后按[刷新与保存顺序](./Tools.md#刷新与保存)同步编辑器。

## 调整 UI

给出 UI 文件、控件路径、目标分辨率和需要保留的交互。

```text
调整指定 UI 文件的信息面板：标题加粗，计数文本居中，保留控件标识、事件和绑定。
在 1920x1080 和 1280x720 下检查文字不被裁切、按钮能点击，并提供截图。
```

**完成标准：**两种分辨率下显示完整，原有交互正常。编辑器预览和游戏内效果都要检查。

## 查找和下载官方资源

1. 说明需要模型、声音、特效还是图标，让 AI 查询候选资源及其 ID。
2. 确认类型与效果后，下载到目标工程。
3. 在编辑器里找到资源并实际加载。

**完成标准：**查询结果、资源 ID 和下载内容一致。具体工具见[官方资源工具](./Tools.md#官方资源工具)。

## 修复报错和整理代码

报错时提供复现步骤、预期/实际结果和完整错误堆栈，使用[问题报告模板](./Troubleshooting.md#发给-ai-的问题报告)。

整理代码时，指出要解决的重复或难读之处，以及必须保留的行为。完成后重跑相关玩法，确认行为一致。

## 结束一轮任务

保留修改文件、实际检查结果和未完成项；可记录到[项目任务文档](./ProjectContext.md)。下一轮从这个记录继续。
