# templates：功能模板

`templates/` 保存 Lua 工具、UI 模块和业务系统。顶层 `ReadMe.md` 是索引，模板内的 `ReadMe.md` 说明接入方法。

## 先看模板等级

目录前缀与说明书中的等级表示复用门槛：

| 等级 | 前缀 | 特点 | 示例 |
| --- | --- | --- | --- |
| A | `a-` 或无前缀 | 通用工具或算法，通常通过参数接入 | `a-event-bus`、`a-number-abbr` |
| B | `b-` | 大多数项目可复用，需要配置或少量回调 | `b-base-panel`、`b-hud-top-info` |
| C | `c-` | 业务逻辑较复杂，需要实现项目适配接口 | `c-shop-system`、`c-bag-system` |
| D | `d-`（如有） | 特定工程专用，移植前需理解原工程 | 以实际库内容为准 |

验证情况另看状态与测试记录。

## 模板说明书里哪些字段最重要

| 字段 | 阅读时要确认什么 |
| --- | --- |
| 适用场景、能力标签 | 是否覆盖当前需求，是否有额外假设 |
| 状态、版本 | 是草稿还是已验证版本 |
| 依赖 | 需要哪些模块、物编数据或其他模板 |
| UI 文件、UI 根节点／资源 | 是否附带界面，需要导入什么资源 |
| Lua 入口、入口签名 | 从哪里加载，初始化时传入什么 |
| 参数、Adapter 接口 | 哪些配置和项目功能需要自己提供 |
| 测试状态 | 在什么工程、条件下验证，是否只使用模拟数据 |
| 集成说明 | 文件放置、初始化、事件连接与清理步骤 |

`draft` 可能通过部分测试，`validated` 也可能只做过结构测试，需按测试范围补充当前工程的集成验证。

## 全部模板

以下按本机 `y3-maker-config/templates/` 的实际目录及各模板 `ReadMe.md` 整理，共 **36 个：A 级 17 个、B 级 12 个、C 级 7 个**，暂无 D 级。不同版本可能增减；每项的完整参数、接口和资源清单见 `.y3maker/templates/模板目录名/ReadMe.md`。

### A 级：通用工具与组件（17 个）

| 模板目录 | 功能与适用场景 | 接入要点 |
| --- | --- | --- |
| `a-aoe-point` | **点范围 AOE**：圆形、矩形及多段范围技能的视觉表现 | 依赖 Y3 API；按说明配置技能参数，使用触发与清理入口 |
| `a-bezier-trajectory` | **贝塞尔弹道**：投射物沿二次／三次曲线飞向单位或点，可转为直线追踪 | 传入投射物、目标对象及速度、加速度等参数 |
| `a-date-time` | **时间工具集**：倒计时格式化、跨天／跨周刷新、签到与时间区间判断 | 可注入服务器时间；返回值需包含 `timestamp`，默认时区偏移为 8 |
| `a-double-check-dialog` | **二次确认弹窗**：删除、退出、购买等操作前确认或取消 | 导入同名 `.upui`，配置挂载位置、文本和回调 |
| `a-dync-component` | **动态 UI 组件基类**：实例化货币条、物品槽、卡牌等 Prefab | 注入 `Class`、本地玩家获取与 UI 元件创建函数；自行准备 Prefab |
| `a-event-bus` | **事件总线**：一次发布，通知 UI、属性等多个模块 | 纯 Lua；支持订阅、取消、发布与清理，注意退出时解除订阅 |
| `a-float-tips` | **浮动文本**：伤害数字、金币获取或状态提示，显示后自动消失 | 必传玩家、文本和父 UI；准备文本元件，并按说明启用鼠标同步 |
| `a-game-fsm` | **父子状态机**：管理游戏阶段、关卡子流程或界面切换 | 配置状态表、迁移关系、初始状态及进入／离开回调 |
| `a-game-timer` | **时间轴调度器**：统一管理 UI 刷新、战斗计时、Buff 倒计时等回调 | 注入带 `loop_frame`、`loop` 的 `y3.ltimer` 对象 |
| `a-number-abbr` | **数字缩写**：将伤害、货币、战力等大数显示为 `1.0w` 等形式 | 纯 Lua；可配置缩写层级与小数位 |
| `a-projectile-line` | **直线投射物**：单发、连发、扇形散射及穿透技能表现 | 依赖 Y3 API；配置发射参数，使用触发与清理入口 |
| `a-random-pool` | **加权随机池**：掉落、刷怪、抽卡和随机事件，可维护多个池 | 注入随机池创建、设权重、查权重与抽取函数，确认当前环境支持对应 API |
| `a-snowflake-id` | **雪花 ID**：为物品、Buff、伤害事件等生成单局内不重复的递增 ID | 使用 `M.nextID()`；依赖 `os.time` 和 Lua 位运算 |
| `a-trace-report` | **HTTP 上报**：错误报告与行为埋点，支持冷却限流和编辑器屏蔽 | 注入请求函数、玩家信息与 JSON 编码器，配置上报目标 |
| `a-tween-timeline` | **补间动画时间线**：编排 UI 位移、缩放、旋转与透明度动画 | 注入帧循环并适配 UI 操作；源码附带补间库许可声明，复用时保留 |
| `a-ui-pool` | **UI 对象池**：复用列表项、浮动文本、卡牌槽或头顶 UI | 注入组件类、挂载节点及实例化函数 |
| `difficulty-select` | **难度选择**：选择玩法模式或难度后进入游戏，支持单／多人大厅 | 说明书标为 A 级；导入 `difficulty-select.upui`，按工程适配 UI 路径和启动流程 |

### B 级：业务与 UI 基础模块（12 个）

| 模板目录 | 功能与适用场景 | 接入要点 |
| --- | --- | --- |
| `b-anim-helper` | **单位动画帧事件**：在动作关键帧触发伤害、音效或连击判定 | 提供帧更新与施法中断事件，确保中断后取消剩余回调 |
| `b-attribute-system` | **属性系统**：管理基础值、装备／Buff 加成、公式依赖、边界和变化监听 | 纯 Lua，运行时需支持 `load`；配置属性与计算公式 |
| `b-base-panel` | **面板基类**：将 `_` 前缀控件自动绑定到面板，支持路径／UUID 查找和显隐 | 注入 `Class`、UI 查询及玩家获取函数，按约定命名控件 |
| `b-base-view` | **视图基类**：统一初始化、显隐、刷新、单例注册与事件回收 | 注入类系统和 GC 容器；子类实现 `initUI`、`updateUI` |
| `b-gm-command` | **GM 指令**：注册加资源、秒杀等测试命令，支持操作录制与回放 | 接入 `y3.develop.command`；核对 `dev_only` 等开发环境限制 |
| `b-hud-main-console` | **底部控制台**：显示选中目标和英雄的属性、血蓝、经验、技能、物品与 Buff | 导入同名 `.upui`，准备配套元件、图标和序列帧资源，接入数据查询与回调 |
| `b-hud-statistic` | **右侧统计面板**：展示玩家伤害、击杀、承伤排行和技能分布 | 导入同名 `.upui`，适配统计元件、玩家信息、技能信息与图标 |
| `b-hud-top-info` | **顶部信息栏**：展示货币、进度等游戏关键数据 | 导入同名 `.upui`，准备货币和进度条元件，接入数据获取与按钮回调 |
| `b-pause-popup` | **暂停弹窗**：通过 ESC 或按钮打开暂停界面，支持单／多人流程 | 导入同名 `.upui`；`setup` 接 UI，`setup_controller` 接暂停控制，配置暂停次数与同步行为 |
| `b-selector-cache` | **缓存区域选择器**：高频索敌、范围预判和目标筛选 | 注入圆形区域创建、单位筛选与敌方组获取函数，同帧复用查询缓存 |
| `b-shield-stack` | **护盾栈**：管理装备、技能、Buff 等多来源护盾，按优先级吸收伤害 | 提供链表与属性读写接口，可接 Buff 绑定、移除及破盾回调 |
| `b-tag-counter` | **标签计数器**：按数量触发羁绊、套装、种族或卡牌流派的阶梯效果 | 配置标签定义及升级／降级／计数变化回调；UI 使用同名 `.upui` 元件 |

### C 级：需适配项目的业务系统（7 个）

Adapter 是一组由当前工程实现的函数，用来连接模板与实际数据、UI 或游戏行为。

| 模板目录 | 功能与适用场景 | 接入要点 |
| --- | --- | --- |
| `c-attr-display-panel` | **属性显示面板**：分区展示属性名称与数值，变化时自动刷新 | Adapter 提供属性读取、变化监听与单元格创建／更新；无需预置 `.upui` |
| `c-bag-system` | **多背包系统**：槽位、堆叠、拾取、移动与交换 | 配置普通／共享背包并实现物品相关 Adapter；不附带 UI |
| `c-game-settle` | **结算面板**：展示胜负、玩家战绩和奖励，适合 1～4 人 PVE／PVP | 导入同名 `.upui`，适配结算数据与回调；UI 参数使用实际路径而非 UUID |
| `c-pick-one-of-many` | **多选一抽卡**：从加权池展示若干候选，支持选择、刷新、放弃和排队 | Adapter 提供卡池、消耗、选择回调及弹窗渲染；纯 Lua，不附带 UI |
| `c-progress-tracker` | **进度追踪**：统一处理成就、任务、图鉴、称号与引导进度 | 配置进度定义，必须提供 `db_load`、`db_save`；奖励和变化回调可选 |
| `c-shop-system` | **商店系统**：货架、购买、多货币定价、折扣与补货 | Adapter 连接货币和物品系统，可组合背包模板；不附带 UI |
| `c-wave-scheduler` | **时间轴关卡调度**：按时间刷新怪物、道具或触发关卡事件 | 配置关卡条目和事件处理函数，提供 tick 驱动；可配合 `a-game-timer` |

以上介绍功能与依赖，不代表已在当前工程验证。索引与单项说明的状态可能不同，接入前应核对单项说明、源码和实际测试结果。

## 建议的复用顺序

1. 从顶层索引选模板，阅读其等级、依赖、输入输出与测试范围。
2. 对照现有模块，确定复用范围与待实现接口。
3. 按说明接入代码和资源，适配路径与标识。
4. 在当前工程验证主要流程和失败情况，记录结果。

顶层模板库复用完整功能；`skills/某技能/templates/` 提供该技能使用的控件 JSON、提示模板等生成素材。
